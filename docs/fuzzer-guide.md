# Using the differential fuzzer

The fuzzer generates random *well-typed* Haskell 2010 programs,
compiles each with AHC, interprets it with GHC 9.4.8, and
byte-compares the stdout. Because the generator's menu is
pre-verified (below), **any divergence is a real finding** — a
compiler bug, never generator noise. It is the project's cheapest
bug-finder: campaigns to date found seven compiler bugs none of
which eleven hand-written harnesses had touched — the
layout-vs-lookahead corner, Integer→Double rounding drift,
negative-zero show, signed-numerator fromRational, two
shortest-round-trip digit bugs (boundary cases and denormals),
and a floored-`mod` overflow that surfaced three layers up as a
mis-reduced Rational.

## Quick start

    scripts/run_fuzz.sh              # 50 seeds starting at 1
    scripts/run_fuzz.sh 300 1        # 300 seeds starting at 1
    scripts/run_fuzz.sh 100 5000     # 100 seeds starting at 5000

Requirements: a built compiler (`alr build --validation`) and the
oracle at `~/.ghcup/bin/runghc` (override with `RUNGHC=`).

Everything is **deterministic**: seed N always produces the same
program (`runghc tests/fuzz/Gen.hs N` shows it), so a finding is
reproducible forever by its seed number — which is why finds are
referred to as "seed 17" in commit messages and war stories.

## Reading the output

One line per seed:

| Line | Meaning | Whose bug |
|---|---|---|
| `ok` | both ran, stdout byte-identical | nobody's |
| `MISMATCH` | both compiled; outputs differ or AHC's exit was nonzero | **AHC** (or, rarely, a generator construct that strayed into undefined territory) |
| `AHC-REJECT` | GHC accepts the program, AHC refuses it | **AHC** — the menu rule guarantees the construct is supported |
| `GEN-ILLTYPED` | GHC rejects the generated program | the **generator** (usually a missing type annotation at an erasure point) |
| `GEN-FAIL` | the generator itself crashed | the **generator** |
| `SLOW-ORACLE` | GHC blew its time budget; the seed is skipped | nobody's (an expensive program) — but a *rash* of these means the generator lost its tractability discipline |
| `SLOW-AHC` | GHC finished, AHC's build or run blew its budget | worth eyeballing: usually an expensive program AHC's naive graph reducer handles worse, occasionally a real runaway |

**Every external step runs under a time limit** (`T_GEN`,
`T_ORACLE`, `T_BUILD`, `T_RUN`, seconds, overridable), so no
generated program can wedge a campaign. This is not paranoia: the
first deep campaign was found six hours in with three oracle
processes pegged at 100% CPU, the harness patiently waiting on
programs that would never finish.

The harness exits nonzero if any seed disagreed.

## Artifacts and triage

Every divergence is saved to `tests/fuzz-failures/` (gitignored):

    seed_57.hs        the full generated program
    seed_57.ghc.out   what GHC printed
    seed_57.ahc.out   what AHC printed (when it ran)
    seed_57.ahc.err   AHC's compile errors (for rejects)
    seed_57.min.hs    the auto-shrunk reproduction
    seed_57.info      provenance: compiler version, commit, time

Check `.info` FIRST when a failure won't reproduce: a saved
artifact is only meaningful against the compiler that produced it
(a resumed orphan job once left a ghost failure from a
mid-milestone binary — hence the stamp, and hence: kill leftover
fuzz jobs before rebuilding the compiler).

Shrinking runs automatically (`scripts/shrink_fuzz.py`, delta
debugging: it deletes main statements and whole definitions while
the same divergence reproduces). The `.min.hs` is where triage
starts:

1. Confirm: run the min program under both compilers yourself.
2. Localize with the stage dumps — `ahc core`, `ahc check`,
   reading the generated C in `<out>.build/` — the shrunk
   expression usually names the guilty stage on sight.
3. If the min is still noisy, bisect by hand: the shrinker only
   deletes whole lines/definitions; simplifying *within* an
   expression (replacing subtrees with literals) is manual and
   usually cracks it in a few steps.
4. Fix, then **pin**: every confirmed find becomes a permanent
   conformance test (its `.out` generated by the oracle) before
   the fix is committed, and the failure files are deleted.
   `ch06_04_negative_zero.hs` is the template.

## Deep campaigns

    scripts/run_fuzz_par.sh 10000 8 1    # 10k seeds, 8 jobs, from 1

The parallel wrapper compiles the generator once (`ghc -O0`,
~20x faster than interpreting it per seed) and splits the range
across jobs; artifacts still land in `tests/fuzz-failures/`
(seed-named, so jobs never collide), and the summary table at the
end aggregates all jobs. Budget roughly 0.3-0.5s per seed per job
on a laptop — 10k seeds across 8 jobs is well under an hour.
Campaign etiquette: run a deep campaign after any milestone that
touches the runtime, codegen, or a generator-menu area, and after
every menu extension (a fresh production historically finds its
first bug within one campaign).

## The menu rule (read before touching Gen.hs)

The fuzzer's value rests on one invariant: **every construct and
library function the generator can emit was first pinned
byte-identical on both compilers**. That is what makes
`AHC-REJECT` a finding instead of noise. So the workflow for
adding a production is:

1. Write a hand kitchen-sink program using the new construct in
   several shapes; run it under BOTH compilers; diff. Only a
   byte-identical construct enters the menu. (If it diverges —
   congratulations, you found a bug the normal way; fix that
   first.)
2. Add the production to `tests/fuzz/Gen.hs`, minding the two
   generator disciplines:
   - **Totality**: never emit a partial application of the
     runtime's mercy. Division is guarded (`let d = e in if d == 0
     then 1 else d`), `maximum` gets a consed head, recursion is
     structural on the match's own tail, exponents are small
     literals.
   - **Tractability — termination is not enough.** A program that
     finishes in 2^n steps is a hang in practice. Two disciplines
     enforce this, both learned the hard way in one campaign: the
     recursive call is LET-BOUND and the generator hands out the
     *variable*, so k uses share one thunk (inlining `(f xs)` at k
     sites is k^depth — a 3^n body was the six-hour wedge); and
     any construct whose cost depends on a VALUE's magnitude is
     clamped, because a Double range's step falls below one ULP at
     large magnitudes (`v + 1.5 == v`), making the range an
     infinite list. When adding a production, ask not only "does
     this terminate?" but "does it terminate in time proportional
     to the syntax I generated?"
   - **Annotate at erasure points**: any consumer that erases its
     argument's element type (`length`, `null`, `fst`/`snd`'s
     other side, case scrutinees, `map`/`mapMaybe` sources) gets
     an inline `:: T` annotation, or an empty-list `sort []`
     underneath becomes ambiguous under GHC and shows up as
     GEN-ILLTYPED.
3. Sweep 30+ seeds for GHC validity, then run a 300-seed
   shakeout, then a deep campaign.

The generator also deliberately AVOIDS territory where divergence
is known and documented rather than wrong (see EXCLUSIONS.md):
Int arithmetic stays far from overflow (the Report leaves it
undefined; AHC promotes), text stays ASCII (Data.Char is
ASCII-only), no `divMod`/`!!` (absent from AHC), and Double
exponents stay modest (literals rounding into the subnormal range
are a documented one-ulp limit of the exact-literal conversion).

## What the menu covers today

Scalars (Int, Integer, Double incl. exponent-form literals, Bool,
Char), an enumeration with the full derive family, a fielded ADT
(`S0`, exercising the pattern matrix and derived Eq/Ord/Show with
negative-field parenthesization), a record (`R0`: construction,
update, selectors), `Either`, `Rational` (exact literals, `%`,
`numerator`/`denominator`, guarded `/` and `recip`,
`fromRational` to Double), lists/Maybe/pairs with ~30 library
functions, `seq` and `foldl'`, lambdas and sections,
comprehensions, ranges (including Double's k-indexed stepping),
guarded and `where`-carrying definitions, structural recursion,
multi-binding `let`, and case eliminators over seven shapes.
