# M146 Int is a machine integer - Implementation Plan

**Goal:** Int arithmetic wraps modulo 2^64 and `fromInteger` narrows, as GHC's;
Int, Char and Integer ranges are lazy and Integer's are correct for bignums;
a strict loop that recurses through a returned thunk runs in constant C stack.

**Architecture:** Int gets its own wrapping primitives in `runtime/ahc_rts.c`,
wired into the `Num Int`/`Integral Int` dictionaries in
`src/ahc-prelude_core.adb`. Integer keeps the promoting ones. The eight
fixed-width types switch their arithmetic carrier from Int to Integer in the
Prelude, because they relied on Int being exact. Integer's enum family moves
to Prelude Haskell. `ahc_eval` updates a thunk to an indirection and loops
instead of recursing on its result.

Spec: `docs/specs/2026-10-05-m146-machine-int.md`.

## Phase A - fixed-width types compute in Integer

The fixed-width instances do `narrowWord64_ (quot (toWord64_ a) (toWord64_ b))`
with `toWord64_ :: Word64 -> Int`. That is correct only while Int is exact:
a `Word64` above 2^63 is a bignum, and Int's `quot` sees it exactly. Phase A
makes the carrier Integer. Under today's runtime this changes no behaviour,
since Int and Integer use the same promoting primitives, so it lands and gates
on its own before Int changes.

- [ ] **Step 1: The operand helper and the overflow raise.** Put them next to

  Put this before `p_add` (~line 2031):

  ```c
  /* An evaluated integer node as a machine word: an AHC_INT's value,
     or a bignum's low 64 bits in two's complement - GHC's
     integerToInt. Int's wrapping primitives read every operand
     through this, so a bignum that reaches Int (a promoting Integer
     result cast by fromIntegral's identity toInteger, a fixed-width
     carrier) is narrowed, never misread through u.i. Limbs are 32
     bits, little-endian. */
  static long int_word(const AhcNode *e) {
    unsigned long mag;
    if (e->tag == AHC_INT) return e->u.i;
    mag = e->u.big.n > 0 ? (unsigned long)e->u.big.d[0] : 0;
    if (e->u.big.n > 1) mag |= (unsigned long)e->u.big.d[1] << 32;
    return (long)(e->u.big.sign < 0 ? 0UL - mag : mag);
  }
  ```

  In `p_narrow`, replace the `if (e->tag == AHC_INT) { ... } else { ... }`
  that computes `low` with `low = (unsigned long)int_word(e);`. This is
  the same arithmetic, now in one place.

- [ ] **Step 2: The primitives.** Put them after `p_from_integer`:

  ```c
  /* Int arithmetic (M146): a 64-bit machine integer, wrapping modulo
     2^64 as GHC's. Computed in unsigned long - signed overflow is
     undefined in C. Integer keeps the promoting p_add family above;
     the two never share a dictionary again. */
  #define WRAP(x) ((long)(x))
  static AhcNode *p_add_w(AhcNode *a, AhcNode *b) {
    long x = int_word(ahc_eval(a)), y = int_word(ahc_eval(b));
    return ahc_mk_int(WRAP((unsigned long)x + (unsigned long)y));
  }
  static AhcNode *p_sub_w(AhcNode *a, AhcNode *b) {
    long x = int_word(ahc_eval(a)), y = int_word(ahc_eval(b));
    return ahc_mk_int(WRAP((unsigned long)x - (unsigned long)y));
  }
  static AhcNode *p_mul_w(AhcNode *a, AhcNode *b) {
    long x = int_word(ahc_eval(a)), y = int_word(ahc_eval(b));
    return ahc_mk_int(WRAP((unsigned long)x * (unsigned long)y));
  }
  static AhcNode *p_neg_w(AhcNode *a) {
    long x = int_word(ahc_eval(a));
    return ahc_mk_int(WRAP(0UL - (unsigned long)x));
  }
  static AhcNode *p_abs_w(AhcNode *a) {
    long x = int_word(ahc_eval(a));
    return ahc_mk_int(x < 0 ? WRAP(0UL - (unsigned long)x) : x);
  }
  /* quot/div of minBound by -1 overflow (GHC raises Overflow);
     rem/mod by -1 are 0 - computing them with % would trap on x86. */
  static AhcNode *p_quot_w(AhcNode *a, AhcNode *b) {
    long x = int_word(ahc_eval(a)), y = int_word(ahc_eval(b));
    if (y == 0) throw_div_zero();
    if (y == -1) {
      if (x == LONG_MIN) throw_overflow();
      return ahc_mk_int(-x);
    }
    return ahc_mk_int(x / y);
  }
  static AhcNode *p_rem_w(AhcNode *a, AhcNode *b) {
    long x = int_word(ahc_eval(a)), y = int_word(ahc_eval(b));
    if (y == 0) throw_div_zero();
    if (y == -1) return ahc_mk_int(0);
    return ahc_mk_int(x % y);
  }
  static AhcNode *p_div_w(AhcNode *a, AhcNode *b) {
    long x = int_word(ahc_eval(a)), y = int_word(ahc_eval(b));
    if (y == 0) throw_div_zero();
    if (y == -1) {
      if (x == LONG_MIN) throw_overflow();
      return ahc_mk_int(-x);
    }
    return ahc_mk_int((x % y != 0 && ((x < 0) != (y < 0))) ? x / y - 1
                                                           : x / y);
  }
  static AhcNode *p_mod_w(AhcNode *a, AhcNode *b) {
    long x = int_word(ahc_eval(a)), y = int_word(ahc_eval(b));
    long r;
    if (y == 0) throw_div_zero();
    if (y == -1) return ahc_mk_int(0);
    r = x % y;               /* opposite signs only: cannot overflow */
    if (r != 0 && ((r < 0) != (y < 0))) r += y;
    return ahc_mk_int(r);
  }
  /* fromInteger at Int narrows (GHC's integerToInt): literals,
     fromIntegral, read and toEnum all reach Int through here. */
  static AhcNode *p_from_integer_w(AhcNode *a) {
    AhcNode *e = ahc_eval(a);
    return e->tag == AHC_INT ? e : ahc_mk_int(int_word(e));
  }
  ```

  Note on the `quot`/`div` order: GHC checks the zero divisor before
  overflow. `0 \`div\` 0` is `divide by zero`, and `minBound \`div\` 0` is
  also `divide by zero`.

  -- for bignums; the C range primitives are Int-only.
  integerSucc_ :: Integer -> Integer

  integerPred_ :: Integer -> Integer
  integerPred_ n = n - 1

  integerEF_ n = n : integerEF_ (n + 1)

  integerEFTh_ :: Integer -> Integer -> [Integer]
  integerEFTh_ n m = go n
    where d = m - n
          go x = x : go (x + d)

  integerEFT_ n m = if n > m then [] else go n
    where go x = x : (if x == m then [] else go (x + 1))

- [ ] **Step 2: The change.** In the THUNK case, replace
  `v = ahc_eval(code(env));` and the update that follows with:

  ```c
        {
          AhcEvalFrame ef;
          AhcNode *v;
          ef.node = n;
          ef.prev = self->eval_top;
          self->eval_top = &ef;
          v = code(env);
          self->eval_top = ef.prev;
          /* M146: do NOT force v recursively - that cost one C frame
             per link of a thunk-returns-thunk chain, so
             `z' `seq` foldl' f z' xs` overflowed the stack at 2*10^7.
             Update n to an indirection to v NOW and loop on v: if v is
             already a value this is the old update exactly; if it is a
             thunk, the next iteration claims it under its own frame.
             An exception while evaluating v rethrows through v, and
             forcing n again follows the IND to the same rethrow.
             Chase v's own indirections first: an IND chain that leads
             back to n (`x = x`) would otherwise become a cycle. */
          while (__atomic_load_n(&v->tag, __ATOMIC_ACQUIRE) == AHC_IND)
            v = (AhcNode *)__atomic_load_n(&v->u.ind, __ATOMIC_ACQUIRE);
          if (v == n) ahc_die("<<loop>>");
          AhcTask *w = (AhcTask *)n->u.bh.waiters;
          __atomic_store_n(&n->u.ind, v, __ATOMIC_RELEASE);
          __atomic_store_n(&n->tag, AHC_IND, __ATOMIC_RELEASE);
  #ifdef AHC_GC_OWN
          own_write_barrier(n);
  #endif
          while (w) {
            AhcTask *nx = w->qnext;
            wake(w);
            w = nx;
          }
          n = v;
        }
        break;
  ```

  Check how today's `<<loop>>` is raised (the `owner == self` branch calls
  `ahc_die("<<loop>>")`). If it's an exception there rather than a die,
  raise it the same way here.

  **Reason through two cases and write the conclusions into the commit
  body:**
  1. **`v` is a blackhole owned by this task, but not `n`.** For example,
     `n`'s code returned an enclosing thunk that is currently being
     evaluated. That thunk's frame is below ours, and the next iteration
     reaches the `AHC_BLACKHOLE` case with `owner == self` → `<<loop>>`.
     This is correct and the same as today's recursive call would have
     done.
  2. **Waiters woken on `n`** re-dispatch, follow `IND` to `v`, and either
     claim it or park on it. No work is duplicated: `v` has exactly one
     claimant.
