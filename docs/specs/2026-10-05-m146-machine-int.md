# M146 - Int is a machine integer, ranges are lazy, strict loops run in constant stack

**Status:** approved design, 2026-10-05.
**Oracle:** GHC 9.4.8 (`~/.ghcup/bin/runghc`); conformance is byte-identical stdout,
exec tests compare `2>&1`.

## Why

The v1.16 performance investigation found four correctness bugs where GHC
succeeds and AHC prints something else, hangs, or crashes. They come before
the extension work (M147) because they are wrong output, not missing features.

| Expression | GHC 9.4.8 | AHC v1.16 |
|---|---|---|
| `maxBound + 1 :: Int` | `-9223372036854775808` | `9223372036854775808` |
| `2 ^ 64 :: Int` | `0` | `18446744073709551616` |
| `fromInteger (2^70 + 5) :: Int` | `5` | `1180591620717411303429` |
| `negate minBound :: Int`, `abs minBound :: Int` | `-9223372036854775808` | `9223372036854775808` |
| `read "18446744073709551617" :: Int` | `1` | `18446744073709551617` |
| ``minBound `div` (-1) :: Int``, `quot` | `arithmetic overflow` | `9223372036854775808` |
| `[2^70 .. 2^70+2] :: [Integer]` | three elements from `1180591620717411303424` | `[12884901889]` |
| `succ (2^70) :: Integer` | `1180591620717411303425` | `12884901890` |
| `take 3 [1..10^9 :: Int]` | instant | builds the whole list first |
| `foldl' (+) 0 [1..2*10^7 :: Int]` | `200000010000000` | stack overflow after 90 s, 3.5 GB |

## Root causes

1. **Int and Integer share one representation and one set of primitives.** An
   Int is an `AHC_INT` word that overflows into a bignum node. `Num Int`,
   `Num Integer` and the wired fixed-width dictionaries call the same
   promoting `p_add`/`p_sub`/`p_mul`/`p_neg`/`p_abs` and `p_quot`/`p_rem`/`p_div`/`p_mod`
   (`src/ahc-prelude_core.adb:1800-1842`, `runtime/ahc_rts.c:2034-2183`).
   `fromInteger` at Int is the identity (`p_from_integer`, ahc_rts.c:2183),
   so literals, `fromIntegral` (`fromInteger . toInteger`), `read` and `toEnum`
   all keep out-of-range values.
2. **Range primitives read `->u.i` without checking for a bignum.**
   `p_enum_from_to` (ahc_rts.c:2558) serves both Int and Integer and builds the
   whole list eagerly in a C loop. `p_enum_from` and `p_succ_integer`/`p_pred_integer`
   (2553-2557) also read the low word of a bignum.
3. **`ahc_eval` recurses when a thunk's code returns another thunk.** The
   THUNK case calls `ahc_eval(code(env))` (ahc_rts.c:~1084), so the chain
   `` z' `seq` foldl' f z' xs `` costs one C frame per element.

## Design

### Unit 1 - Int arithmetic wraps modulo 2^64

- **New primitives** in `runtime/ahc_rts.c` for `Num Int` and `Integral Int`:
  `+`, `-`, `*`, `negate`, `abs`, `quot`, `rem`, `div`, `mod`, `quotRem`, `divMod`.
  - They compute in `unsigned long` and convert back, which is two's
    complement wrapping without C undefined behaviour. They never allocate
    a bignum.
  - Each operand is read through one helper, `int_word(AhcNode *)`. For an
    `AHC_INT` it returns the word; for a bignum it returns the low 64 bits in
    two's complement, the same narrowing as `p_narrow`. That keeps the
    fixed-width types correct: `Word64` values above 2^63 can still reach Int
    arithmetic as bignums.
  - `div`/`quot`/`divMod`/`quotRem` by zero raise `divide by zero`, as today.
    `minBound` divided by `-1` raises `arithmetic overflow`, matching GHC's
    `ArithException` text and its `try`/`evaluate` behaviour.
    `minBound` `mod`/`rem` `(-1)` is `0`.
- **`fromInteger` at Int narrows** to the low 64 bits (GHC's `integerToInt`).
  `toInteger` at Int stays the identity, because an Int is always an
  `AHC_INT` now.
- **Wiring:** `src/ahc-prelude_core.adb` gives the `Int_TC` branch the new
  primitives (new `BP` bindings, `Def_Global` types, `runtime/ahc_rts.h`
  externs). `Integer_TC` keeps the promoting ones. The wired `Is_Fix` branch
  keeps the promoting ones too: source instances in the Prelude override it
  for every fixed-width type, and the plan confirms no fixed-width program
  reaches it.
- **Unchanged:** `Bits Int` (it already wraps through `low64`), `succ`/`pred`
  at Int (they already raise GHC's messages), and the fixed-width types'
  Prelude source.
- **Possible gain:** the wrapping primitives have no overflow branch and no
  bignum fallback, so Int-heavy loops may get faster. The bench decides.

### Unit 2 - lazy ranges, correct at Integer

- **Int:** `enumFromTo` returns `lo > hi ? NIL : mk_enum_ftl(lo, 1, hi)`. This
  uses the existing lazy generator (ahc_rts.c:2427-2470) that `[a..]` and
  `[a,b..c]` already use. Char inherits it through `map chr [ord a .. ord b]`.
- **Integer:** `enumFrom`, `enumFromTo`, `enumFromThen`, `enumFromThenTo`,
  `succ` and `pred` become Prelude Haskell over Integer `+` and comparison, in
  the shape of `fixedEnumFromTo_`. That makes them lazy and correct for any
  magnitude. The wired Enum dictionary's `Integer_TC` branch
  (prelude_core.adb:2100-2130) binds to them instead of the C primitives.
- The Int-only C primitives keep reading `->u.i`. Unit 1 guarantees an Int is
  never a bignum, which is now a stated invariant with a contract or a C
  assert at each entry point.

### Unit 3 - constant-stack evaluation

- In `ahc_eval`'s THUNK case, the result of `code(env)` is no longer forced
  recursively. The node is updated to `IND v` immediately, through the same
  release stores, waiter wake-up and `own_write_barrier` as today. The eval
  frame is popped, and the loop continues with `n = v`.
  - If `v` is already in weak head normal form, this is exactly today's
    update.
  - If `v` is another thunk, the next iteration claims it with its own frame.
- **Semantics preserved:**
  - **Exceptions.** An exception raised inside `code(env)` still finds `n`'s
    frame. Once `n` is `IND v`, an exception while evaluating `v` belongs to
    `v`'s frame. Forcing `n` again follows the indirection and re-raises from
    `v`, as GHC does.
  - **`<<loop>>`.** Re-entering `n` while `v` is under evaluation reaches `v`'s
    blackhole owned by the same task, so it still reports `<<loop>>`.
  - **Concurrency.** Waiters parked on `n` wake, follow the indirection, and
    either claim `v` or wait on it. No work is duplicated.
- **What this does not cover:** a strict loop whose recursion goes through a
  direct call rather than a returned thunk. The plan measures `foldl'`,
  `mapM_`/`forM_` over a long list, and a hand-written accumulator loop with
  `seq`, and records which of them run in constant stack.

## Error handling and GHC text

- `arithmetic overflow` and `divide by zero` reach `show` and stderr exactly
  as GHC prints them. Exec tests pin both the uncaught form (`<prog>: arithmetic overflow`)
  and the `try`/`evaluate` form.
- Out-of-range Int literals compile and narrow, as GHC does. GHC's
  `-Woverflowed-literals` warning is not reproduced, since AHC does not match
  GHC's warnings.

## Gates

- **Conformance**, new oracled programs:
  - `lib_int_overflow`: arithmetic at the bounds, `^`, `negate`/`abs`
    `minBound`, `quotRem`/`divMod` table, `mod`/`rem` by `-1`.
  - `lib_int_narrowing`: `fromInteger`, `fromIntegral`, literals, `read`,
    `toEnum`.
  - `lib_fixed_width_bounds`: every Int8-Int64 and Word8-Word64 type at its
    bounds under `+`, `-`, `*`, `negate`, `fromIntegral`.
  - `lib_integer_ranges`: the four enum forms and `succ`/`pred` over bignums,
    `take` of infinite Integer ranges.
- **Exec**, oracled `2>&1`:
  - the uncaught and caught `arithmetic overflow`;
  - `foldl'` over `[1..10^8]` in constant stack;
  - `take 3 [1..10^18]`;
  - the stack-depth table from Unit 3.
- **Suites:** full gate in both GC modes, both differential suites, and
  `run_examples`, `run_separate`, `run_export`, `run_repl`.
- **Runtime checks:** own-collector soak with `AHC_OWN_VERIFY=1`, and TSan,
  because `ahc_eval` changes.
- **Fuzz:** 300 seeds. The plan checks whether the fuzz generator has avoided
  Int overflow until now; if so, it widens the literal range.
- **Bench:** best-of-5 interleaved against v1.16, recorded in CHANGES.
- **Release process:** adversarial review, a security pass only if the FFI's
  Int marshalling changes, then the write-up, then release v1.17.

## Out of scope

- Direct saturated calls, method resolution at known instances, GC tuning and
  clang `-O2`: the performance milestone.
- LambdaCase, FlexibleInstances, TypeSynonymInstances,
  GeneralizedNewtypeDeriving: M147.
- `-Woverflowed-literals` and other GHC warnings.
