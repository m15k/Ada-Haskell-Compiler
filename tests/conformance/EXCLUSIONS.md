# Haskell 2010 Report features not exercised by this conformance subset

The suite covers what AHC implements; these Report features are known
gaps, excluded deliberately rather than tested weakly. Each entry is
the reason a conformance program does not exist for it.

| Report | Feature | Status |
|---|---|---|
| 5 | Module system corners | multi-module programs WORK (imports with qualified/as/hiding/lists, export lists incl. `T(..)`/`C(..)`, abstract types, cycle/ambiguity/not-exported errors); restricting the implicit Prelude import WORKS per Report 5.6.1 (`hiding`, only-lists, `import Prelude ()`, `qualified` - the explicit import replaces the implicit one, filters the qualified view too, and builtin syntax `()`/`[]`/`:`/tuples stays in scope; ext_prelude_*.hs conformance + bad_prelude_*.hs both-reject differentials). ~~Still flat: same-named type synonyms or data constructors in two modules are a compile error.~~ Since M75 every namespace is per-module: two modules may declare the same type, constructor, class, synonym, record field or value, a qualified import disambiguates (`L.Shape`, `R.Circle`, `L.radius`, `instance R.Named T`), an unqualified use of two different imported entities is an ambiguity error at the use site (Report 5.5.2), and so are conflicting exports (Report 5.2); declaring a name twice WITHIN one module is still an error (4.2.1). Only builtins and the Prelude are program-global (multi/dupnames, multi/dupsyn, multi/ambig, multi/m75_*). One deliberate OVER-ACCEPTANCE remains: a module's own top-level declaration WINS over a same-named import or Prelude entity at an unqualified use, where GHC reports "Ambiguous occurrence" - long-standing for values (`map x = x` in a module shadows the Prelude's), and kept for types, constructors and classes so the two namespaces behave alike; qualify the name to be GHC-portable. Code generation, C compilation and linking are separate and per-module (content-hash object cache; scripts/run_separate.sh); the FRONTEND stays whole-program by design - no interface files - which is what gives Report program-wide instance coherence for free |

| 6.3.4 | ~~`Enum` at Char/Double~~ WORKS | `['a'..'z']`, succ/pred/to/fromEnum at Char; Double numeric enumeration with GHC's k-indexed stepping and the half-step limit (ch06_03_enum_char_double.hs); Bool/Ordering enum now ride the enumeration-derive machinery (`[False ..]` works) |
| 11.1 | deriving covers ENUMERATIONS for Enum/Bounded/Ix; ~~Read~~ derives for EVERY shape | `Eq`/`Ord`/`Show`/`Read` derive for all shapes. `deriving Read` is generated as the exact inverse of derived Show (M141): prefix constructors at `readParen (d > 10)` with fields at 11, infix at `(d > 9)` with fields at 10, records through their brace/label/equals/comma lexemes with fields at 0, and a nullary constructor through `readParen False` so "(C)" reads. Non-nullary deriving Enum/Bounded/Ix is still REJECTED at compile time ("all constructors must be nullary" - bad_derive_nonnullary.hs pins both-compilers-reject; GHC additionally accepts single-constructor Bounded/Ix products, which stay honestly unimplemented) |
| 3.14 | ~~`fail` at `Maybe`/`[]`~~ WORKS | refutable do-binds fail to Nothing / skip per the Report (ch03_14_faildo.hs); IO's fail errors, as GHC's does |
| ch. 4 | Class-hierarchy corners | `Functor`/`Applicative` (pure/`<*>`/`*>`/`<*`/`<$>`, ch04_applicative.hs) and `Read` work at Maybe/[]/IO, and `Either a` is Functor/Applicative/Monad as base has it (ch04_02_newtype_patterns.hs); `Monad` does NOT have `Applicative` as superclass (the 2010 shape - `return` and `pure` are separate but agree), BUT a Monad instance omitting `return` gets base's default: the whole-program frontend solves Applicative at the instance head and takes its `pure` (lib_monadplus.hs) |
| 4.2.3 | Newtype `seq` divergence | newtype constructor PATTERNS are irrefutable per the Report (`f (N _) = 1` accepts `undefined` - ch04_02_newtype_patterns.hs, the fix that lets some/many terminate on newtype parsers), but the wrapper is still a real runtime node, so `seq (N undefined) ()` is `()` where GHC (which erases newtypes) diverges; observable only through seq/`($!)` on an undefined-wrapped value |
| 9, lib 42 | ~~Exceptions~~ WORK: `ioError`/`userError`/`IOError` in the Prelude, `System.IO.Error`, a closed `Control.Exception` | Report 9's Prelude entries and Library Report 42 are complete except `ioeGetHandle`/`ioeSetHandle` (the handle field is never stored; the `Maybe Handle` arguments of `mkIOError`/`annotateIOError` are accepted and ignored). IOErrors raised by the runtime carry GHC's fields - the type from errno, libc's text as the description, the path as the filename, the operation as the location (`readFile` at `openFile`, `writeFile`/`withFile` at `withFile`) - so `show` is byte-identical (ch07_ioerror.hs, lib_system_io_error.hs). `Control.Exception` is base-compat like Applicative: `SomeException`, the `Exception` class, `ErrorCall`, `ArithException`, `IOException`, `ExitCode` (an exception, as in GHC), `throw`/`throwIO`/`catch`/`handle`/`try`/`evaluate`/`bracket`/`bracket_`/`finally`/`onException` (lib_control_exception.hs). `SomeException` is CLOSED: a program cannot declare its own exception type (needs `Typeable`; Haskell 2010 has none). Deliberate divergences: `show` of an `ErrorCall` raised by `error` omits GHC's `CallStack` suffix (the `ErrorCall m` pattern agrees in both); pattern-match failure raises `ErrorCall` with AHC's message, not `PatternMatchFail` with GHC's span text; `<<loop>>` and deadlock are fatal reports, not `NonTermination`/`BlockedIndefinitely` values; refinement and contract violations are uncatchable by design; no asynchronous exceptions (`throwTo`, `timeout`, `mask`); `exitWith` inside a spawned task propagates to the scope's join like any exception and ends the process with that code (GHC's forkIO thread prints `ExitFailure n` to stderr and the process continues); an exception inside an FFI *callback* is fatal at the callback boundary (GHC propagates it to the Haskell caller of the foreign call); an uncaught `ExitFailure n` with n > 255 exits 255 like GHC, and a negative n exits 255 where GHC kills the process with signal -n; `ExitFailure 0` is GHC's catchable `exitWith: invalid argument (ExitFailure 0)`. Docs: docs/exceptions-design-note.md |
| 4.5.5 | Monomorphism restriction, Rule 1 | A restricted group (a simple pattern binding without a signature) is not generalized AT ALL in AHC, where the Report withholds generalization only from CONSTRAINED type variables: `let xs = [] in (length (1 : xs), length (True : xs))` is accepted by GHC and rejected here ("no instance for Num Bool"). Constrained bindings agree with GHC (ch04_05_mr_case_scrutinee.hs), and a desugarer temporary is monomorphic by the same rule - which is what makes `case` on a class method's result typecheck |

| 9 | The uncaught-exception banner is `ahc:`, not the program's name | GHC's top-level handler prints `<progname>: <message>`; AHC prints `ahc: <message>`, and for an `ErrorCall` it prints `ahc: error: <message>` where GHC prints just the message (no `error: `). | 11 | A derived Show/Read on an unsupported FIELD type fails at run time, not compile time | GHC rejects `data F = F (Int -> Int) deriving Read` with "No instance for (Read (Int -> Int))". AHC's derives resolve each field's dictionary statically and, finding none, emit an `error` in its place - so the program compiles and says "deriving Read: unsupported field type" when that field is first read. Derived Show has behaved this way since it was written; M141's derived Read follows the same convention rather than inventing a second one. The shapes that matter (every type whose fields are themselves Read/Show instances) are unaffected |
